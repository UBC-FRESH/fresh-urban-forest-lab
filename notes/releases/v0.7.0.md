# v0.7.0

Status: released. Tag: `v0.7.0`.
Date: 2026-11-15.

## What this is

The street-level tree candidate release. It keeps the v0.6.0 scientific products and Walk
mode and adds an open, separate street-level tree candidate layer for Vancouver.

## What changed

- Added the `fresh_urban_forest.street_trees` package module:
  - KartaView public imagery provider;
  - documented pinhole projection and FOV assumption;
  - metric-depth geolocation;
  - multi-view candidate fusion;
  - public-inventory matching;
  - separate GeoJSON candidate contract.
- Added the optional `street` dependency group and an operator pilot using OneFormer and
  ZoeDepth.
- Published a Vancouver pilot layer with **24** fused candidates.
- Added `has_street_trees`, `GET /api/street-trees`, and `GET /api/street-trees.geojson`.
- Added a separate teal `street trees` map layer and toggle.
- Added a screening-point popup with view count and positional uncertainty.
- Added P63/P64 tests, documentation, and reports.

## Not changed

- No scientific product, data claim, default layer, or corrected-product threshold changed.
- Street candidates are **not merged** with the LiDAR off-inventory layer, official
  inventory, or corrected products.
- Walk mode and the v0.6.0 data products are unchanged.

## Limits

- The street layer is a Commercial Drive pilot, not a citywide inventory.
- KartaView FOV is assumed at 60°; imagery is from 2016 and the inventory is current.
- OneFormer plus distance-peak splitting is a screening pipeline, not a trained
  tree-instance detector.
- No field validation, private-tree census, ownership, survival, or citywide precision
  claim.
- The public inventory is incomplete for private trees.
